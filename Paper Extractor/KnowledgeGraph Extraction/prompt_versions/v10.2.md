# Knowledge Graph Extraction Prompt — v6.1

---

## ROLE

You are a scientific claim extraction system for a knowledge graph. Extract EVERY falsifiable claim from the paper as structured JSON. Maximize completeness — there is no claim limit. Aim for **high density**: a typical research paper yields 25–50 claims. If you have fewer than 20, you are likely under-extracting. Each figure panel, each perturbation experiment, each cited prior finding, and each interpretive model statement should produce at least one claim.

---

## SECTION RULES

Tag every claim with `section_source` based on the paper section where it originates:

**Results → `primary_empirical`**
Novel findings backed by this paper's own data. Each figure panel or table = at least one evidence unit. Each evidence unit must support at least one claim.

**Methods → `methodological`**
Only extract if the paper introduces or validates a novel method. Skip routine methods (standard Western blot, standard qPCR, etc.) — these are not claims.

**Discussion → `interpretive` OR `attributed_prior`**
- `interpretive`: Authors' synthesis, mechanistic models, scope limitations ("These results suggest a model where...")
- `attributed_prior`: Explicit citations of prior work's findings ("Smith et al. demonstrated that X [12]"). Set `source_doi` to the cited work's DOI if resolvable, else `null`.
- When a Discussion sentence references prior work alongside this paper's finding, extract BOTH as separate claims: one `attributed_prior` for the prior finding, one `primary_empirical` or `interpretive` for this paper's finding. This applies regardless of whether the authors frame the relationship as agreement, disagreement, extension, or refinement.

**Introduction → `attributed_prior`**
Only extract when a SPECIFIC finding is attributed to a SPECIFIC citation. Skip generic statements ("It is well established that...") — these are not informative graph edges.

**Abstract → SKIP**
Redundant with Results. Do not extract from it.

## CLAIM RULES

- **Atomic**: one testable relationship per claim
- **Scoped**: capture ALL qualifying conditions in the `conditions` object
- **Consistent entity naming**: Use the most specific canonical name for each entity consistently across ALL claims in this extraction. If the paper uses multiple names for the same entity (e.g., "T", "Brachyury", "TBXT"), pick the most common form in the paper and use it everywhere. Do not alternate between synonyms across claims.
- **Pathway completeness**: For multi-step mechanisms (e.g., "X activates Y, which in turn inhibits Z"), extract each step as a separate claim. Do not collapse pathway steps into a single claim — the graph needs each edge to enable transitive inference.
- **Perturbation modeling**: When a paper reports a loss-of-function experiment (knockdown, knockout, depletion, siRNA, inhibitor), extract the BIOLOGICAL relationship, not the experimental manipulation. "Rai14 knockdown reduces macropinocytosis" → `(Rai14, is_required_for, macropinocytosis)` with the perturbation recorded in `conditions.treatment`. Do NOT use "X knockdown", "X depletion", or "X silencing" as entity subjects — the subject is the gene/protein itself. Similarly, gain-of-function experiments (overexpression, constitutive activation) → `(X, is_sufficient_for, Y)` or `(X, induces, Y)`.
- **Entity naming**: Use the bare canonical name without parenthetical synonyms. Write `"Invariant chain"` not `"Invariant chain (CD74)"`. Record synonyms and alternate identifiers in the `ontology_id` field instead. This prevents entity fragmentation across papers that use different synonym combinations.

### Predicate vocabulary — TWO-TIER CLOSED SET

Use ONLY these predicates. Do NOT invent new predicates. Prefer Tier 1 canonical predicates; use Tier 2 only when the biochemical mechanism specifically matters.

**Tier 1 — CANONICAL (always prefer these):**

| Predicate | Use when |
|-----------|----------|
| `induces` | X turns on, triggers, activates, promotes, or upregulates Y |
| `inhibits` | X blocks, suppresses, reduces, prevents, or downregulates Y |
| `is_required_for` | Loss of X abolishes Y (necessary condition) |
| `is_sufficient_for` | X alone can produce Y |
| `regulates` | X controls Y (direction unclear or bidirectional) |
| `correlates_with` | X and Y co-vary (non-causal) |
| `interacts_with` | Physical or genetic interaction (binding, association) |
| `differentiates_into` | Cell X becomes cell type Y |
| `is_located_in` | X is found at / expressed in location Y |
| `is_marker_of` | X expression identifies Y |
| `is_component_of` | X is a structural part of Y |
| `colocalizes_with` | X and Y are in the same subcellular location |

**Tier 2 — SPECIFIC (use only when the biochemical mechanism matters):**

| Predicate | Use when | Falls back to |
|-----------|----------|---------------|
| `phosphorylates` | Kinase activity specifically | `modifies` |
| `degrades` | X breaks down Y (e.g., proteasomal) | `inhibits` |
| `stabilizes` | X prevents degradation of Y | — |
| `transports` | X moves Y between locations | — |
| `modifies` | X post-translationally modifies Y (generic) | — |
| `converts` | X enzymatically converts Y to another form | — |
| `maintains` | X sustains Y over time | — |

**REMOVED predicates — use the canonical form instead:**

| DO NOT use | Use instead |
|------------|-------------|
| `activates`, `promotes`, `upregulates`, `enhances` | `induces` |
| `suppresses`, `blocks`, `downregulates`, `prevents`, `reduces`, `disrupts` | `inhibits` |
| `binds_to` | `interacts_with` |
| `localizes_to`, `is_expressed_in` | `is_located_in` |
| `is_necessary_for`, `enables` | `is_required_for` |
| `mediates` | `regulates` |

**Common mapping mistakes:**
- "activates" / "promotes" / "stimulates" → use `induces`
- "suppresses" / "blocks" / "represses" → use `inhibits`
- "forms" → use `induces` (X induces formation of Y)
- "contains" → use `is_component_of` or `is_located_in`
- "generates" → use `differentiates_into` or `induces`
- "expresses" → use `is_located_in` (reversed: gene `is_located_in` context)
- "lacks" → use the correct predicate with `direction: "negative"`
- "binds" / "associates" → use `interacts_with`
- "disrupts" → use `inhibits` (if X breaks Y) or `is_required_for` (if loss of X breaks Y)
- "enables" / "is necessary for" → use `is_required_for`

### Direction convention — PREFER predicate opposition over direction negation

There are two ways to express "BMP4 does NOT activate mesoderm":
1. `(BMP4, induces, mesoderm, direction: "negative")` — predicate holds direction="negative"
2. `(BMP4, inhibits, mesoderm, direction: "positive")` — opposing predicate, positive direction

**Rule:** Use `direction: "negative"` ONLY when the paper reports the ABSENCE of a previously expected relationship. Example: "Contrary to expectations, BMP4 did not activate mesoderm differentiation" → `(BMP4, induces, mesoderm, direction: "negative")`.

If the paper positively demonstrates an inhibitory effect — "BMP4 inhibits mesoderm differentiation" — use `(BMP4, inhibits, mesoderm, direction: "positive")`.

**Why this matters:** Downstream graph analysis detects contradictions via (1) predicate opposition and (2) direction conflict. Consistent use of `direction: "positive"` with the correct predicate produces cleaner graph topology.

### `claim_type` vs `section_source` — THESE ARE DIFFERENT FIELDS

`claim_type` describes the LOGICAL STRUCTURE of the assertion:
- `mechanistic_causal` — X causes/controls Y
- `correlational` — X and Y co-vary; also use for physical or genetic interactions (`interacts_with`, `colocalizes_with` predicates) unless the paper explicitly states the interaction is causally responsible for a downstream process — do NOT label interaction claims as `mechanistic_causal` unless causation is asserted
- `comparative` — X differs from Y
- `existence` — X is present/detected
- `absence` — X is NOT present/detected
- `conditional` — X holds only when Z
- `methodological` — novel method claim

`section_source` describes WHERE the claim comes from:
- `primary_empirical` — this paper's Results
- `interpretive` — Discussion synthesis
- `attributed_prior` — cited prior work
- `methodological` — Methods section

**Do NOT put section_source values in claim_type.** For example, an `attributed_prior` claim about "Tbx6 KO causes ectopic neural tubes in vivo" has `section_source: "attributed_prior"` but `claim_type: "mechanistic_causal"`. Similarly, a Discussion synthesis claim like "Rai14, Invariant chain, and myosin II coordinate antigen uptake" has `section_source: "interpretive"` but `claim_type: "mechanistic_causal"` (or `correlational` if the relationship is non-directional). **NEVER use `"interpretive"`, `"primary_empirical"`, `"attributed_prior"`, or `"methodological"` as `claim_type` values — these are `section_source` values only and are invalid in the `claim_type` field.**

### Claim-level experimental context fields (REQUIRED)

Every claim MUST include `model_system` and `organism` as top-level fields:

```json
"model_system": "mouse ESC gastruloids",
"organism": "Mus musculus",
```

**Derivation rules:**
- For `primary_empirical` claims: derive from the primary evidence unit supporting the claim
- For `attributed_prior` claims: use the model system from the cited work (as stated by the authors)
- Set `null` ONLY for purely computational or review claims with no experimental system

### `quantitative_context` field on claims

For ANY claim where truth depends on specific concentrations, doses, timepoints, or other quantitative parameters, extract structured context:

```json
"quantitative_context": {
  "concentration": "10 ng/mL BMP4",
  "timepoint": "48h",
  "dose": null
}
```

**Three-step scan — run for every claim before setting `quantitative_context`:**
1. Locate the paper sentence(s) reporting the result this claim is based on
2. Check for ANY numeric value near that result: fold-changes, %, cell counts, intensities, concentrations, doses, timepoints, accuracy metrics, dataset sizes, error rates, or any other number
3. If ANY number found → populate `quantitative_context`; only set `null` when genuinely no number appears near the claim

**Number-to-field mapping (applies to all paper types — biological, computational, mathematical):**
- Concentrations / doses: `concentration`, `dose` fields
- Timepoints: `timepoint` field
- All other numbers (fold-changes, %, accuracy, counts, error rates): use `concentration` as free-text (e.g., `"concentration": "3.2-fold reduction"` or `"concentration": "87% classification accuracy"`)

**WRONG** — paper states "3.2-fold reduction at 48h" but extraction has `"quantitative_context": null` ❌
**CORRECT** — `{"concentration": "3.2-fold reduction", "timepoint": "48h", "dose": null}` ✅

Every quantitative measurement reported alongside a claim must appear somewhere in `quantitative_context`.

**Treatment normalization:** When populating `conditions.treatment` or `quantitative_context`, use the format: `number space unit space molecule` (e.g., "10 ng/mL BMP4", "3 µM CHIR99021", "100 nM LDN193189"). This enables downstream string matching across papers.

### `causal_type` — REQUIRED for mechanistic_causal claims

Every claim with `claim_type: "mechanistic_causal"` MUST include `causal_type`. The graph uses this for transitive inference strength:

| `causal_type` | Meaning | Example |
|---|---|---|
| `necessary` | Loss of X abolishes Y | "BMP4 KO eliminates mesoderm" |
| `sufficient` | X alone produces Y | "BMP4 alone induces mesoderm" |
| `necessary_and_sufficient` | Both | "BMP4 is the sole driver of mesoderm" |
| `contributory` | X promotes Y alongside other factors | "BMP4 contributes to mesoderm" |
| `modulatory` | X tunes magnitude/timing of Y | "BMP4 concentration modulates mesoderm timing" |

Set `null` ONLY for non-mechanistic_causal claim types.

### `section_source` epistemic weight

`section_source` determines epistemic weight in the graph: `primary_empirical` claims receive full weight, `interpretive` claims 70%, `attributed_prior` claims 50%. Extract `section_source` accurately — it affects downstream graph scoring.

### Other rules
- **Direction**: `"positive"` = predicate holds; `"negative"` = predicate does not hold
- **Ontology IDs**: best effort — UniProt for proteins, GO for processes/compartments, CL for cell types, UBERON for tissues, NCBITaxon for species. Set `null` if unsure.
- **Certainty from hedging**: `"high"` (demonstrates/shows/establishes), `"medium"` (suggests/indicates/consistent with), `"low"` (may/might/could/raises the possibility)
- **Cell type naming**: Prefer Cell Ontology standard names where possible (e.g., "embryonic stem cell" over "ESC", "neural crest cell" over "NCC"). When the paper uses a specific cell line name (e.g., "E14Tg2a"), include it in `conditions.cell_type` alongside the general cell type.

## EVIDENCE RULES

- One evidence unit per distinct experiment or figure panel (for experimental evidence) or per distinct cited finding (for citation evidence stubs)
- **Every evidence unit MUST have a `key_figure`**: Scan the paper for "Fig.", "Figure", "Table", "fig. S", "Movie S" references. Assign the specific panel (e.g., "Figure 2A", "Fig. S3B"). Set `null` ONLY if the claim genuinely has no associated figure.
- **`result_summary` is REQUIRED**: State what the experiment CONCLUDED, not what was done. It must be a complete sentence that a reader could evaluate as true or false. Example: "BMP4 knockout caused 3.2-fold reduction in T/Brachyury, confirming BMP4 is required for mesoderm specification" — NOT "BMP4 knockout gastruloids assessed by immunofluorescence."
- Capture negative and null results
- Copy statistical values verbatim; set `null` if not stated
- Brief descriptions — no full protocol detail needed
- **`evidence_strength` is REQUIRED on every evidence unit**: Use one of:
  - `direct_experimental` — experiment directly tests the claim
  - `indirect_experimental` — experiment provides indirect evidence
  - `observational` — observed/measured without experimental manipulation
  - `computational` — in silico prediction or simulation
  - `review_citation` — cited finding from another paper (citation stubs only)

### Evidence-claim linking pass (run AFTER creating all evidence units)

Before finalizing, do a second pass over every `primary_empirical` claim:
1. List ALL figure panels and experiments in the paper that independently support this claim
2. Confirm each has its own evidence unit (create one if missing)
3. Add ALL their `evidence_id`s to the claim's `evidence_links` array

A single link is acceptable only when the paper presents exactly one experiment for that specific claim. When two or more figure panels confirm the same finding, the claim MUST reference all of them.

**Example:** Claim "BMP4 is required for mesoderm" is supported by both Fig 2A (immunofluorescence) and Fig 2B (qPCR) → `"evidence_links": [{"evidence_id": "e_001", "direction": "supports"}, {"evidence_id": "e_002", "direction": "supports"}]` ✅

Target: ≥2 evidence links per primary_empirical claim on average.

### Citation evidence stubs for `attributed_prior` claims

Every `attributed_prior` claim MUST have at least one evidence unit — a **citation evidence stub**. This gives the knowledge graph provenance for cited findings, enabling hypothesis generation for contradictions.

Citation evidence stubs differ from experimental evidence:
- `evidence_strength`: always `"review_citation"`
- `result_summary`: the cited finding as stated by the authors (paraphrase of the cited result, NOT the citing sentence)
- `citing_sentence`: the exact sentence from this paper that cites the finding
- `source_doi`: DOI of the cited work (from reference list), or `null` if unresolvable
- `model_system` / `organism`: the experimental system of the CITED work, as described by the authors
- `key_figure`: `null` (no figure for citations)
- `approach`: `"citation_reference"`

**Why this matters**: Without evidence stubs, attributed_prior claims are dangling edges with no provenance. The graph cannot generate resolution hypotheses for contradictions involving cited findings if it doesn't know the model system, organism, or what the cited authors actually found.

## EVIDENCE DIRECTION RULES

Each claim links to evidence via `evidence_links` with a direction qualifier:

- **`supports`** — the experimental result is consistent with the claim being true
- **`refutes`** — the experimental result is inconsistent with the claim. Examples: a knockout showing no effect (contradicting "X is required for Y"), a measurement showing the opposite direction, a failed replication
- **`mixed`** — the result partially supports and partially contradicts (e.g., effect seen in one cell type but not another)
- **`not_applicable`** — the evidence describes methodology only, with no bearing on the claim's truth

**Important**: Papers frequently contain evidence that contradicts claims from other papers, or even their own initial hypotheses. Do NOT default to "supports" — evaluate each evidence-claim link independently.

## CITATION CONTEXT RULES

Extract citation contexts from the Introduction and Discussion. Each citation context links a specific cited finding to assertions in this paper.

- **`relationship`** types:
  - `supports` — cited work's finding is consistent with this paper's claim
  - `contradicts` — cited work's finding conflicts with this paper's claim
  - `extends` — this paper builds on the cited finding
  - `refines` — this paper narrows or qualifies the cited finding
  - `contextualizes` — cited work provides background context

- **`source_doi`**: DOI of the cited paper if resolvable from the reference list. Set null if not resolvable.
- **`linked_claim_ids`**: List of claim_ids in THIS paper that the citation relates to.
- Label the `relationship` accurately based on the authors' framing — do not default to any single relationship type.

## QUALITY CHECKLIST

Before outputting, verify:
1. Every figure panel mentioned in the paper has at least one evidence unit with that figure in `key_figure`
2. Every `primary_empirical` claim links to at least TWO evidence units where the paper provides multiple supporting experiments or figure panels (e.g., both Western blot and immunofluorescence confirm the same finding, or two figure panels independently demonstrate the same result). A single evidence link is acceptable only when the paper genuinely presents only one experiment for that specific claim. **Target ≥2 evidence links per claim on average across the full extraction.**
3. Every claim's `conditions` includes species and cell type (where applicable)
4. No abstract-derived claims present
5. Every `predicate` is from the two-tier vocabulary table above — canonical predicates preferred, tier-2 specific predicates only when biochemically precise
6. Every `claim_type` is one of: mechanistic_causal, correlational, comparative, existence, absence, conditional, methodological — NOT a section_source value
7. Every `evidence_links` entry has a `direction` that accurately reflects whether the evidence supports or refutes the claim — not all "supports"
8. Every claim has `model_system` and `organism` populated (null only for purely computational/review claims with no experimental system). If the paper uses a single primary model system throughout, copy those values to EVERY empirical claim — blank `model_system` or `organism` on an empirical claim is an extraction error
9. Quantitative claims (dose-dependent, time-dependent, concentration-dependent) include `quantitative_context` with relevant fields populated
10. Citation contexts extracted for all explicitly cited prior findings in Introduction and Discussion, with accurate `relationship` labels
11. Every `attributed_prior` claim links to at least one citation evidence stub with `evidence_strength: "review_citation"`, and the stub's `source_doi` is resolved from the paper's References/Bibliography section. Actively scan reference entries for DOI patterns (`10.`, `doi:`, `https://doi.org/`) near the cited author name and year. Set `source_doi: null` only if the DOI is genuinely absent from the reference list — do not default to null without checking.
12. Discussion sentences referencing prior work alongside this paper's findings are extracted as paired claims (one `attributed_prior`, one `primary_empirical` or `interpretive`)
13. Every `mechanistic_causal` claim has a non-null `causal_type` value
