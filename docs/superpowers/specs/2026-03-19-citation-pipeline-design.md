# Citation Pipeline Design: Eliminating Drop-offs & Reference Match Mode

**Date:** 2026-03-19
**Status:** Draft v2
**Author:** Claude (brainstormed with user)

## Problem Statement

The AutoReview pipeline currently loses 91.3% of corpus papers between search and final citation. Two structural drop-offs exist:

1. **Drop 1 (49% loss)**: Corpus expansion (Stage 11) adds papers after the outline is built (Stage 8), so late-added papers are never assigned to sections.
2. **Drop 2 (83% loss)**: Section writers receive flat, unranked paper lists with no citation budget or priority guidance, resulting in implicit and inconsistent citation selection.

These are not tunable behaviors — they are pipeline defects. This spec eliminates both by restructuring the pipeline and adding a citation selection stage.

## Design Principles

1. **Drop prevention is default behavior, not a setting.** The pipeline always builds outlines on the complete corpus and always provides ranked citation lists to writers.
2. **Settings control citation policy, not pipeline correctness.** Density, priority weights, tier distribution, and style are configurable. Whether papers get lost is not.
3. **Reference match copies structural profile, never content.** When matching a reference paper, the pipeline calibrates word count, citation density, section count, and citation style. It never copies, biases toward, or is influenced by the reference paper's actual citations or bibliography.

## Pipeline Architecture Change

### Current Pipeline (broken)
```
Search → Screen → FT → Extract → Cluster → GapSearch
  → Outline → Narrative → Enrich → Expand → Write → Assembly → Polish
```

Outline sees ~790 papers. Expansion adds ~500 more that are never assigned.

### New Pipeline (correct by construction)
```
Search → Screen → FT → Extract → Cluster → GapSearch
  → Draft Outline (haiku, lightweight)
  → Enrich → Expand
  → Final Outline (sonnet, full corpus)
  → Narrative → Citation Selection → Write → Assembly → Polish
```

- **Draft Outline**: Cheap (haiku model). Produces topic buckets and section structure — just enough to target enrichment queries. No paper assignments needed.
- **Final Outline**: Full outline generation (sonnet). Sees the complete corpus (all papers from search + gap search + enrichment + expansion). Assigns papers to sections from the full pool.
- **Citation Selection**: New mandatory stage. Ranks assigned papers, assigns tiers, computes per-section citation budgets, and produces annotated paper lists for the writer.

### New DAG Nodes

| Node | Model | Input | Output |
|------|-------|-------|--------|
| `DraftOutlineNode` | haiku | EvidenceMap, scope | DraftOutline (topic buckets, section structure) |
| `FinalOutlineNode` | sonnet | Full corpus extractions, EvidenceMap, DraftOutline | ReviewOutline with paper_ids from complete corpus |
| `CitationSelectionNode` | deterministic Python (scoring) + optional haiku (citation_guidance text) | ReviewOutline, all extractions, CitationConfig | CitationPlan (tiered, budgeted paper lists per section) |

**Note on CitationSelectionNode model assignment:** The ranking algorithm is pure math — no LLM needed. The optional `citation_guidance` string per paper can be generated by haiku or via template string. This keeps the stage fast and deterministic. Validation gate: every section has a CitationPlan with ≥1 primary paper.

The `.claude/skills/run-local/skill.md` stage list must be updated to reflect this 16-stage pipeline.

### EvidenceWeightedAllocator Placement (C3)

`EvidenceWeightedAllocator.allocate()` MUST run at the end of `FinalOutlineNode`, NOT `DraftOutlineNode`. The draft outline does not need word count allocation — it only produces topic buckets and section structure for enrichment targeting.

### Draft Outline Enrichment Guard Behavior (C4)

The "skip if well-covered" guard (section.paper_ids >= 15) is **intentionally disabled** during the draft outline phase. The draft outline does not have paper_ids populated, so the guard cannot use that field. Alternative: use theme paper counts from the EvidenceMap to determine coverage for enrichment targeting — not outline paper_ids. This is an intentional behavior change from the pre-split pipeline.

## Configuration Model

### CitationConfig (new Pydantic model)

```python
class CitationConfig(BaseModel):
    """Controls citation policy — how aggressively and selectively to cite."""

    model_config = ConfigDict(extra="forbid")  # matches WritingConfig pattern

    # Density
    citation_density: Literal["sparse", "standard", "dense", "exhaustive"] = "standard"
    min_citations_per_section: int = 8
    max_citations_per_section: int | None = None
    target_corpus_utilization: float = 0.25  # % of score-4+ papers to cite

    # Selection strategy
    selection_strategy: Literal[
        "evidence_weighted", "recency_weighted",
        "diversity_optimized", "impact_weighted", "balanced"
    ] = "balanced"

    # Paper tiering
    paper_tiers_enabled: bool = True
    tier_distribution: dict[str, float] = {
        "primary": 0.30,      # individually discussed
        "supporting": 0.50,   # cited in clusters for consensus
        "contextual": 0.20,   # background/context citations
    }
    seminal_paper_boost: float = 1.5  # priority multiplier for foundational works

    # Priority scoring weights (must sum to 1.0)
    w_evidence_strength: float = 0.30
    w_recency: float = 0.20
    w_relevance_score: float = 0.25
    w_uniqueness: float = 0.15
    w_source_diversity: float = 0.10

    # Citation style
    cluster_citations: bool = True        # allow [1-5] for consensus
    max_cluster_size: int = 5
    require_individual_discussion: Literal[
        "primary_only", "all_tiers", "none"
    ] = "primary_only"

    # Coverage constraints
    min_sources_per_theme: int = 2
    temporal_spread: bool = True
    contradiction_citation_mode: Literal[
        "both_sides", "stronger_side", "all"
    ] = "both_sides"
    gap_paper_priority: Literal["boost", "normal", "deprioritize"] = "boost"

    # Writer guidance
    writer_citation_hints: Literal[
        "none", "ranked_list", "annotated_tiers", "budget_with_tiers"
    ] = "budget_with_tiers"
    uncited_paper_warning: Literal["ignore", "warn", "force_include"] = "warn"

    @model_validator(mode='after')
    def validate_weights_sum_to_one(self) -> 'CitationConfig':
        """Priority scoring weights must sum to 1.0."""
        total = (
            self.w_evidence_strength
            + self.w_recency
            + self.w_relevance_score
            + self.w_uniqueness
            + self.w_source_diversity
        )
        if abs(total - 1.0) >= 1e-6:
            raise ValueError(
                f"Citation scoring weights must sum to 1.0, got {total:.6f}"
            )
        return self
```

**Note on domain YAML overrides (C2):** `CitationConfig` uses `extra="forbid"` to match the `WritingConfig` pattern. Domain YAML files do NOT need to include citation config — defaults apply automatically. Domain-level YAML overrides for citation config are out of scope for v1.

### ReferenceMatchConfig (new)

```python
class ReferenceMatchConfig(BaseModel):
    """Auto-calibrate citation settings to match a reference paper's structural profile.

    IMPORTANT: This matches structural characteristics only (word count, citation
    density, section count, citation style). It NEVER copies, biases toward, or is
    influenced by the reference paper's actual citations or bibliography content.
    """
    model_config = ConfigDict(extra="forbid")  # NEW (m2)

    enabled: bool = False
    reference_path: Path | None = None

    # Auto-extracted targets (populated by pre-pipeline analysis)
    target_word_count: int | None = None
    target_citation_count: int | None = None
    target_citation_density: float | None = None  # refs per 1K words
    target_section_count: int | None = None
    inferred_citation_style: str | None = None     # numbered vs author-year

    # Tolerances for validation gate
    word_count_tolerance: float = 0.15   # +/- 15%
    citation_count_tolerance: float = 0.20  # +/- 20%

    # What to match
    match_word_count: bool = True
    match_citation_density: bool = True
    match_section_structure: bool = True
    match_citation_style: bool = True
```

**Override cascade:**
```
depth preset defaults → reference_match overrides → user explicit overrides (highest priority)
```

**Pre-pipeline analysis** reads the reference PDF and extracts:
- Word count → overrides DepthProfile.total_word_budget
- Reference count → overrides CitationConfig density targets
- Refs/1K words → overrides target_citations_per_1k_words
- Section headings → guides outline required_sections
- Citation format (numbered [1] vs author-year) → overrides WritingConfig.citation_format

**Reference PDF parse failure fallback (m7):** If reference count cannot be parsed (malformed PDF, missing References section), log a WARNING and use the depth preset defaults instead of reference-derived targets. The `target_citation_count` field remains `None`, and validation gates that depend on it are skipped.

**Assembly validation gate:** After assembly, compare generated review metrics against reference targets. If metrics are outside tolerance, log a WARNING with the specific deviations (e.g., "citation count 82, target 120 ± 20%"). A revision pass is NOT triggered automatically — the assembly critique loop handles quality improvements. Reference match validation is informational only. (m3)

## Citation Selection Algorithm

The CitationSelectionNode runs after Final Outline, before Section Writing.

**Note on CitationPlan freeze:** The CitationPlan is frozen after CitationSelectionNode. Papers added by passage_search (Stage 14) are treated as additive — they bypass CitationPlan validation. The CitationValidator checks: (a) all PRIMARY papers from the plan are cited, (b) total citations are within budget tolerance, (c) passage_search additions are flagged as "additive" not "plan violations." (M5)

### Input
- ReviewOutline with paper_ids per section
- All extractions (full corpus)
- CitationConfig

### Algorithm

For each section:

1. **Score each assigned paper:**
   ```
   score = (w_evidence * evidence_strength_score
          + w_recency * recency_score
          + w_relevance * relevance_score
          + w_uniqueness * uniqueness_score
          + w_diversity * source_diversity_score)
          * seminal_boost_if_applicable
   ```

   Where:
   - `evidence_strength_score`: strong=1.0, moderate=0.7, weak=0.4, preliminary=0.2
   - `recency_score`: linear scale, newest=1.0, oldest=0.0 within date range
   - `relevance_score`: screening score normalized to 0-1 (score 5=1.0, 3=0.4)
   - `uniqueness_score` (M1): 1.0 if the paper is the only paper in this section assigned to a theme cluster not covered by any other paper in the section. 0.5 if the paper's theme cluster has ≤3 other papers in this section. 0.0 if the paper's theme cluster has >3 other papers in this section. Theme cluster = the paper's primary theme from `EvidenceMap.paper_theme_mapping`.
   - `source_diversity_score` (M2): `1.0 - (count_of_papers_from_same_database / total_assigned_papers)`. "database" = the `source_database` field on `CandidatePaper` (pubmed, semantic_scholar, openalex, etc.). Clamped to [0.0, 1.0].
   - `seminal_boost`: multiply by `seminal_paper_boost` if paper qualifies as seminal (M3):
     - (a) `paper_id` appears in `consensus_claim.supporting_paper_ids` for any consensus claim where `consensus_claim.evidence_count >= 10`, OR
     - (b) `paper_id` is the first element of any `evidence_chain.paper_ids` list (the chronological origin of the chain)

2. **Compute section citation budget:**
   ```
   section_budget = section_word_count * target_citations_per_1k_words / 1000
   budget = max(budget, min_citations_per_section)
   if max_citations_per_section:
       budget = min(budget, max_citations_per_section)
   # Apply assignment floor after clamping:
   budget = min(budget, len(assigned_papers))
   ```

3. **Assign tiers** (ranked by score):
   - Top `tier_distribution["primary"]` % → PRIMARY (must be individually discussed)
   - Next `tier_distribution["supporting"]` % → SUPPORTING (cited in clusters for consensus)
   - Remaining `tier_distribution["contextual"]` % → CONTEXTUAL (background citations)

   **Fractional tier boundary handling (M4):**
   - Use `ceil()` for primary count (ensures at least 1 primary paper)
   - Use `floor()` for contextual count
   - Remainder goes to supporting
   - Float-to-int conversion uses `round()` (standard rounding). Example: 13.7 → 14, 13.4 → 13. (m6)
   - If a section has fewer than 3 papers, all are PRIMARY (no tiering applied).

4. **Apply coverage constraints:**
   - Ensure at least `min_sources_per_theme` different databases represented
   - If `temporal_spread`: ensure citations span early, middle, and recent periods
   - If `contradiction_citation_mode == "both_sides"`: both sides of contradictions get at least one primary paper
   - If `gap_paper_priority == "boost"`: gap-fill papers get +0.2 score boost

### Output: CitationPlan

```python
class PaperCitation(BaseModel):
    paper_id: str
    tier: Literal["primary", "supporting", "contextual"]
    priority_score: float
    citation_guidance: str  # e.g., "Discuss individually — strongest evidence for claim X"

class SectionCitationPlan(BaseModel):
    section_id: str
    citation_budget: int
    primary_papers: list[PaperCitation]
    supporting_papers: list[PaperCitation]
    contextual_papers: list[PaperCitation]
    coverage_notes: list[str]  # e.g., "Ensure temporal spread from 2020-2025"

class CitationPlan(BaseModel):
    sections: dict[str, SectionCitationPlan]
    total_citation_budget: int
    corpus_utilization_target: float
```

## Writer Prompt Changes

The section writer prompt currently receives a flat list of paper extractions. With this change, it receives:

```
## Citation Budget: ~{budget} references for this section

### PRIMARY papers (discuss individually):
1. [@paper_id_1] — {claim}. Evidence: {strength}. {guidance}
2. [@paper_id_2] — ...

### SUPPORTING papers (cite in clusters for shared claims):
3. [@paper_id_3] — ...
4. [@paper_id_4] — ...

### CONTEXTUAL papers (cite for background/framing):
5. [@paper_id_5] — ...

### Citation instructions:
- You MUST cite all PRIMARY papers with individual discussion
- Cluster SUPPORTING papers where they support the same claim (e.g., [3,4,5])
- CONTEXTUAL papers are optional — use for framing or if word budget allows
- Target approximately {budget} total citations in this section
```

## Depth Presets (bundles)

`exhaustive` is both a `DepthLevel` enum value and a `CitationConfig` density preset. The `DepthProfile` for `EXHAUSTIVE` must be added to `_DEPTH_PROFILES` (see DepthProfile extensions above).

| Preset | Density | Strategy | Cluster | Target Util | Min Refs |
|--------|---------|----------|---------|-------------|----------|
| `low` | sparse | evidence_weighted | true | 0.10 | 25 |
| `medium` | standard | balanced | true | 0.25 | 75 |
| `deep` | dense | diversity_optimized | true | 0.40 | 150 |
| `exhaustive` | exhaustive | balanced | true | 0.60 | 300 |

`reference_match` mode overrides these with values extracted from the reference paper.

## Success Criteria

- Drop 1 eliminated: 100% of corpus papers are available for outline assignment
- Drop 2 reduced: corpus utilization matches target (±tolerance)
- Reference match mode: generated review within tolerance of reference paper's structural profile
- No regression: existing pipeline behavior preserved when citation config uses defaults
- All existing tests pass
